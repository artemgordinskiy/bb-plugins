PR Watcher wakes the thread that owns a pull request when something changes that you can act on: CI fails or recovers, a reviewer leaves feedback, or the PR is approved, green and ready to merge. The agent gets a short message saying what changed, checks the failures or comments and proposes fixes for you to approve, so you don't have to check GitHub and nudge it by hand. A pass after a pass, such as after a rebase, and an approval with no comment don't wake anyone. It only wakes threads. It never pushes, replies on GitHub or requests reviewers, and it tells the agent to ask you before doing any of those.

A watch starts only when someone asks for one: the agent calls `pr_watch` after opening a PR, or you run `bb pr-watcher watch`. Each PR has one owner thread, and a later claim moves it; `--from` moves all of a child's watches before the child is stopped. Wakes wait until the owner and everything running under it have been quiet, and several changes arrive as one message. Every rule is a setting with these defaults, and a change applies on the next poll. `bb pr-watcher status` shows what each thread watches and why a wake is waiting, and `unwatch` stops one watch or all of them.

GitHub text is cleaned, cut short and framed as untrusted data, and agents are told not to follow it. The plugin reads PRs with `gh` on the machine that holds the checkout, so it uses that machine's GitHub login and needs no token of its own. A wake is recorded before it is sent, so an interrupted send can lose a wake but never repeats one.
