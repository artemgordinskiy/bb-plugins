PR Watcher wakes the thread that owns a pull request when CI settles or a reviewer leaves feedback. The agent gets a short message saying what changed and picks up the failures or comments itself, so you don't have to check GitHub and nudge it by hand. It only wakes threads. It never pushes, replies on GitHub or requests reviewers, and it tells the agent to ask you before doing any of those.

A watch starts only when someone asks for one: the agent calls `pr_watch` after opening a PR, or you run `bb pr-watcher watch`. Each PR has one owner thread, and a later claim moves it. Wakes wait until the owner and everything running under it have been quiet for two minutes, and several changes arrive as one message. Feedback counts when it comes from repository owners, members and collaborators, or from a review by a bot you list. `bb pr-watcher status` shows what each thread watches and why a wake is waiting, and `unwatch` stops it.

GitHub text is cleaned, cut short and framed as untrusted data, and agents are told not to follow it. The plugin reads PRs with `gh` on the machine that holds the checkout, so it uses that machine's GitHub login and needs no token of its own. A wake is recorded before it is sent, so an interrupted send can lose a wake but never repeats one.
